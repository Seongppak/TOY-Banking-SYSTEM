# TOY-Banking-SYSTEM

C 콘솔 뱅킹 프로그램입니다. 기존 업무 함수와 작업 내역 조회 흐름을 유지하면서
TXT 파일 기반 계좌 관리 및 신규 사용자 등록을 지원합니다.

프로그램 함수는 `bandking.c`에서 정의하고 `banking.h`에 선언합니다.
`main.c`는 헤더를 포함하여 메뉴와 입력을 처리하고 함수를 호출합니다.
이체의 양쪽 잔액 변경, 파일 저장 및 실패 시 복구는
`transfer_between_accounts()` 내부에서 처리합니다.

## Visual Studio 빌드 및 실행

- 기존 솔루션 또는 `니마이 완성을 위한 프로젝트/니마이 완성을 위한 프로젝트.vcxproj`를 엽니다.
- 프로젝트의 기존 도구 집합은 v145이며 Windows SDK와 C++ 데스크톱 개발 도구가 필요합니다.
- Debug/Release, x64/Win32 구성을 사용할 수 있습니다.
- 디버거 실행 시 작업 폴더는 프로젝트 폴더입니다. EXE를 직접 실행할 때도
  `customer_info.txt`가 있는 폴더를 작업 폴더로 사용하십시오.
- 최초 빌드 시 출력 폴더에 TXT를 복사합니다. 이미 있는 출력 폴더의 데이터는
  재빌드 시 덮어쓰지 않습니다. 디버거와 출력 폴더 직접 실행은 각각의 TXT를 사용합니다.

## 계좌 파일과 입력

`customer_info.txt`를 **UTF-8**로 저장합니다. BOM 유무 모두 읽을 수 있으며,
저장은 BOM 없는 UTF-8로 수행합니다. CP949 파일은 UTF-8로 변환한 뒤 사용하십시오.
활성 C 소스 및 헤더는 UTF-8 BOM을 사용하며, main.c와 bandking.c는 `/utf-8`로
컴파일합니다. Windows 콘솔 입력과 출력도 UTF-8로 설정합니다.

각 줄의 형식은 `계좌번호 비밀번호 이름 잔액`입니다.
계좌번호는 양수인 long long, 비밀번호는 0~32767인 short, 잔액은 0 이상인
long long입니다. 이름은 공백 없이 UTF-8 기준 최대 19바이트입니다
(한글 음절은 일반적으로 3바이트이므로 최대 6글자).
최대 계좌는 100개이며, 잘못된 줄·중복 계좌·범위 초과가 있으면 파일 전체를
오류로 처리하고 기존 파일을 덮어쓰지 않습니다. 빈 파일에서는 첫 사용자를
등록할 수 있습니다. 파일이 없으면 오류로 종료합니다.

시작 메뉴에서 로그인, 신규 등록, 종료를 선택합니다. 중복 계좌 등록은
비밀번호를 추가로 묻지 않고 즉시 취소하여 시작 메뉴로 돌아갑니다.
신규 계좌 잔액은 0원입니다. 등록 및 입금·출금·이체 후 전체 계좌를
임시 파일에 기록하고 Windows의 파일 교체 기능으로 반영합니다.
저장 실패 시 등록/거래를 취소하며, 정상 종료 및 입력 종료 시에도 저장합니다.

## 테스트

Visual Studio Developer Command Prompt에서 Python 3로 실행합니다.

```text
python -X utf8 tests/test_banking.py
```

실제 main.c 및 bandking.c를 MSVC `/W4 /WX /utf-8`로 빌드하고,
임시 폴더에서 파일 오류 검사와 실행 검사를 수행합니다.
초기 잔액, 입출금, 계좌별 분리, 등록, 중복 취소, 재시작 후 유지,
비밀번호, 기존 로그 출력, 최대 계좌 수, 입력 범위, 저장 실패 시 복구를 검사합니다.
이체의 양쪽 잔액 반영, 재시작, 잘못된 수취 계좌, 본인 계좌, 잔액 부족,
수취 잔액 초과, 저장 실패 시 취소도 검사합니다.
원본 customer_info.txt에는 테스트 데이터를 쓰지 않습니다.

## 계좌 간 이체

이체를 선택하면 송금 계좌의 비밀번호, 수취 계좌번호, 이체 금액을 입력합니다.
등록된 다른 계좌로만 이체할 수 있습니다. 송금 잔액 부족, 0 이하 금액,
잘못된 입력, 수취 잔액의 long long 범위 초과 시 잔액을 변경하지 않습니다.
성공 시 송금 계좌에서 차감하고 수취 계좌에 즉시 입금하여 양쪽 잔액을
한 번의 파일 저장으로 반영합니다. 저장 실패 시 양쪽 잔액을 모두 복구하며
실패한 이체는 거래 내역에 기록하지 않습니다. 프로그램 종료 전에도 TXT에
반영되므로 수취 계좌로 다시 로그인하면 입금된 잔액을 조회할 수 있습니다.

## 기존 기능의 한계

- 작업 내역은 기존 struct log 배열에 최대 20개를 메모리로 저장합니다.
  재실행 후 거래 내역을 복원하는 기능은 기존에도 없으며 이번에도 추가하지 않았습니다.
- 기존 흐름대로 작업 내역 확인에 동의하면 이름 확인 및 조회 후 프로그램이 종료됩니다.
- 임시 파일 방식은 단일 프로그램 실행을 전제로 합니다. 여러 인스턴스의 동시 수정은 지원하지 않습니다.
