# TOY-Banking-SYSTEM

C 콘솔 뱅킹 프로그램입니다. 기존 업무 함수와 작업 내역 조회 흐름을 유지하면서
TXT 파일 기반 계좌 관리 및 신규 사용자 등록을 지원합니다.

## Visual Studio 빌드 및 실행

- 기존 솔루션 또는 `니마이 완성을 위한 프로젝트/니마이 완성을 위한 프로젝트.vcxproj`를 엽니다.
- 프로젝트의 기존 도구 집합은 v145이며 Windows SDK와 C++ 데스크톱 개발 도구가 필요합니다.
- Debug/Release, x64/Win32 구성을 사용할 수 있습니다.
- 디버거 실행 시 작업 폴더는 프로젝트 폴더입니다. EXE를 직접 실행할 때도
  `customer_info.txt`가 있는 폴더를 작업 폴더로 사용하십시오.
- 최초 빌드 시 출력 폴더에 TXT를 복사합니다. 이미 있는 출력 폴더의 데이터는
  재빌드 시 덮어쓰지 않습니다. 디버거와 출력 폴더 직접 실행은 각각의 TXT를 사용합니다.

## 계좌 파일과 입력

`customer_info.txt`와 C 소스 및 헤더는 **CP949**로 저장합니다.
MSVC는 `/source-charset:.949 /execution-charset:.949`로 컴파일하고,
Windows 콘솔 입력과 출력도 코드 페이지 949로 맞추어야 합니다.
프로그램 내부의 Windows API 호출은 제거했습니다. 빌드한 EXE의 전체 경로를
`니마이 완성을 위한 프로젝트/run_cp949.cmd "EXE 전체 경로"`에 전달하면
콘솔 코드 페이지를 949로 바꾸고 프로젝트 폴더의 계좌 파일을 사용합니다.
이 실행은 실제 계좌 파일을 저장하므로 시험할 때는 EXE, CMD와 계좌 TXT의
복사본을 별도 폴더에 두고 그 폴더의 CMD를 실행하십시오.
명령 프롬프트에서는 `chcp 949`를 실행한 후 EXE를 실행해도 됩니다.
Visual Studio F5/CTRL+F5 실행 시에도 입력 및 출력 콘솔이 949인지 확인하십시오.
UTF-8 콘솔을 그대로 사용하면 한글 표시와 한글 명령 비교가 맞지 않습니다.
Windows Terminal에는 한글을 지원하는 글꼴(예: D2Coding)을 선택하십시오.
한글 입력은 IME로 입력하며 C 소스에 콘솔 설정용 API를 넣지 않습니다.
IDE 편집기에서 파일이 깨져 보이면 인코딩으로 열기에서 한국어 코드 페이지 949를
선택하십시오. README와 보고서는 UTF-8/Office 형식이며 계좌 TXT와 다릅니다.

각 줄의 형식은 `계좌번호 비밀번호 이름 잔액`입니다.
계좌번호는 양수인 long long, 비밀번호는 0~32767인 short, 잔액은 0 이상인
long long입니다. 이름은 공백 없이 CP949 기준 최대 19바이트입니다
(한글 음절은 2바이트이므로 최대 9글자).
읽기는 `rb` 모드로 수행하여 Windows 텍스트 모드의 Ctrl+Z 파일 끝 처리로
뒤의 잘못된 자료가 숨겨지지 않도록 했습니다. 줄 끝 CRLF는 직접 정리합니다.
최대 계좌는 100개이며, 잘못된 줄·중복 계좌·범위 초과가 있으면 파일 전체를
오류로 처리하고 기존 파일을 덮어쓰지 않습니다. 빈 파일에서는 첫 사용자를
등록할 수 있습니다. 파일이 없으면 오류로 종료합니다.

시작 메뉴에서 로그인, 신규 등록, 종료를 선택합니다. 중복 계좌 등록은
비밀번호를 추가로 묻지 않고 즉시 취소하여 시작 메뉴로 돌아갑니다.
신규 계좌 잔액은 0원입니다. 등록 및 입금·출금·이체 후 전체 계좌를
임시 파일에 기록하고 표준 C의 `rename()`과 `remove()`로 반영합니다.
저장 실패 시 등록/거래를 취소하며, 정상 종료 및 입력 종료 시에도 저장합니다.

## 기존 기능의 한계

- 이체는 기존 구현대로 송금 계좌에서 차감만 합니다. 수취 계좌 선택과
  수취 계좌 입금이 구현되어 있지 않습니다. 이번 변경에서는 유지했습니다.
- 작업 내역은 기존 struct log 배열에 최대 20개를 메모리로 저장합니다.
  재실행 후 거래 내역을 복원하는 기능은 기존에도 없으며 이번에도 추가하지 않았습니다.
- 작업 후 “네”를 선택하면 이름 확인과 내역 조회를 거쳐 시작 메뉴로 돌아갑니다.
  “아니오”는 바로 시작 메뉴로 돌아갑니다. 다른 계좌 로그인 시 작업 내역은 초기화됩니다.
  작업 메뉴의 “메인메뉴”도 시작 메뉴로 돌아가며, 시작 메뉴의 3번으로 종료합니다.
- 임시 파일 방식은 단일 프로그램 실행을 전제로 합니다. 여러 인스턴스의 동시 수정은 지원하지 않습니다.

## 저장 절차와 복구

1. 원본을 읽을 수 있는지 확인하고 기존 `.tmp`나 `.bak`가 있으면 저장을 중단합니다.
2. 모든 계좌를 `.tmp`에 쓰고 `fprintf`, `fflush`, `fclose`의 결과를 확인합니다.
3. 원본을 `.bak`로 이름 변경한 뒤 `.tmp`를 원본 이름으로 변경합니다.
4. 교체가 실패하면 `.bak`를 원본 이름으로 되돌립니다. 복구도 실패하면
   `.bak`와 `.tmp`를 보존하고 오류를 출력합니다.
5. 교체가 성공한 뒤 `.bak`를 삭제합니다. 삭제만 실패하면 저장 성공과
   백업 정리 실패를 구분해 알립니다. 남은 백업은 다음 저장을 막습니다.

여러 번의 이름 변경을 사용하므로 전체 저장은 원자적이지 않습니다.
중간에 강제 종료되면 원본 이름의 파일이 없거나 보조 파일이 남을 수 있습니다.
프로그램을 종료하고 각 파일을 **먼저 별도 복사**하여 내용을 비교하십시오.
원본이 없으면 `.bak`는 마지막 기존 데이터이고 `.tmp`는 저장하려던 새 데이터입니다.
확인한 파일의 복사본을 `customer_info.txt`로 복원하고, 확인이 끝난 보조 파일을
별도 보관 폴더로 옮긴 후 재실행하십시오. 자동 복구나 디스크 강제 동기화는 제공하지 않습니다.
저장 함수는 현재 프로그램처럼 이미 존재하는 계좌 파일을 전제로 합니다.
빈 파일은 지원하지만 없는 파일을 임의로 새로 만들지 않습니다.

## 최종 검증과 보고서

Visual Studio 2026 Community의 v145 도구 집합과 Windows SDK로
Debug/Release × x64/Win32 네 구성을 빌드했습니다. C17과 C 컴파일을
명시하고 경고 수준을 `/W4`로 설정했습니다. 저장소 루트 솔루션의
개인 컴퓨터 경로를 프로젝트 상대 경로로 수정했습니다.

필수 TC-01~TC-30, 추가 TC-31~TC-42 및 재실행 준비 2회를 포함한
44개 실행 검사를 수행했습니다. 실제 프로그램 실행과 별도 함수 검사 드라이버를
구분하고, 저장 복구 실패는 테스트 전용 오류 주입으로 검증했습니다.
원본 계좌 파일 두 개는 CP949 바이트 검사와 SHA-256 비교로 보존을 확인했습니다.
별도 복사본에서 CP949 실행 CMD와 Ctrl+Z 뒤의 잘못된 자료 거부도 추가 확인했습니다.

- PDF 보고서: `reports/TOY-Banking-SYSTEM-final-report.pdf`

IDE F5 화면을 캡처한 결과는 포함하지 않았습니다. 보고서의 콘솔 장면은
MSVC 빌드 실행 파일의 실제 표준 출력에 입력값을 해당 프롬프트에 삽입한 재현입니다.
원본 stdout과 전송한 입력값은 검증 기록에 따로 보존합니다.

비밀번호는 학습용 TXT에 평문으로 저장됩니다. 실제 금융 서비스에는 사용할 수 없습니다.

계좌번호로 업무 메뉴에 들어갑니다. 메뉴 진입과 입금에서는 비밀번호를 묻지 않으며, 출금·이체·잔액조회에서 비밀번호를 확인합니다.
